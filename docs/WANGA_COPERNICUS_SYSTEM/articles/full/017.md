# קופסה בתוך קופסה

## רעיון מרכזי

קופסה בתוך קופסה מתאר תופעה שבה מערכת מוסיפה שכבות כדי להתמודד עם קושי, אך כל שכבה יורשת חלק מהנחות השכבה הקודמת. התוצאה יכולה להיות מערכת מורכבת יותר שאינה בהכרח חופשית יותר.

## Recursive Convergence

כאשר כל תיקון מתבצע בתוך אותה נקודת ייחוס, האפשרויות החדשות מתכנסות שוב אל אותו מרחב. זה אינו בהכרח כשל של הלוגיקה המקומית. כל תיקון יכול להיות עקבי בפני עצמו. הבעיה היא שהמערכת אינה בודקת את המסגרת שממנה היא מתחילה.

מכאן ההבדל בין **תיקון** לבין **Reframing**. תיקון משנה רכיב בתוך המבנה. Reframing בודק האם המבנה עצמו עדיין משרת את הדרישה.

## ארכיטקטורה

WANGA משתמש ברצף: **Requirement → Reference Point → Box Detection → Perspective → Reconstruction → Verification**. כאשר מזהים קופסה בתוך קופסה, אין צורך לפרק את כל המערכת. צריך לזהות איזו שכבה קובעת את ההחלטה ומהן ההנחות שהיא מעבירה לשכבות שמתחתיה.

## פעולה

המתודה כוללת מיפוי של שכבות, זיהוי יחסי תלות, הפרדת דרישות מאילוצים, וחזרה לאחור מן התוצאה הנדרשת אל התנאים שמאפשרים אותה. כך ניתן להוציא רכיב שימושי ממסגרת אחת ולהציב אותו במקום אחר בלי לשחזר את כל המבנה.

## מערכת חיה

אם הארכיטקטורה ממשיכה להשתנות, נדרשת לולאת אימות. **Observe → Represent → Reason → Act → Verify → Update Memory → Observe** מונעת מהפתרון להפוך לקופסה בלתי נראית חדשה.

## סיכום

קופסה בתוך קופסה מראה שמורכבות אינה מדד מספק להתקדמות. מערכת יכולה לצבור שכבות ועדיין להישאר כלואה באותה נקודת ייחוס. היציאה היא לא עוד שכבה, אלא בדיקה של היחס בין הדרישה לבין הארכיטקטורה.
