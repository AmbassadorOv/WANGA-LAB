# איך קופסה נוצרת

**WANGA Copernicus System — Article 012 / 100**

## הטענה

איך קופסה נוצרת עוסק בהבדל בין בעיה לבין המסגרת שבה הבעיה הוגדרה. קופסה היא אוסף גבולות, הנחות ויחסים שמאפשרים למערכת לפעול, אך גם קובעים מראש מה ייחשב פתרון. הפעולה הקופרניקנית היא להפוך את הקופסה עצמה לנצפית.

## ארכיטקטורת החשיבה

המתודה מתחילה ב**דרישה**, לא בארכיטקטורה קיימת. מן הדרישה מזהים **נקודת ייחוס**, ממנה את הגבול, ומהגבול את היחסים שמבנים את המערכת. רק אז בונים ארכיטקטורה. זהו הסדר: **Requirement → Reference Point → Boundary → Relations → Architecture → Implementation**.

לוגיקה רציונלית נותנת למערכת עקביות פנימית. המאמר הזה עוסק בתוצאה הרחבה יותר: עקביות פנימית אינה מוכיחה שהמסגרת מתאימה לדרישה. לכן צריך לבדוק גם את תנאי ההפעלה של ההסקה.

## פירוק והרכבה

במקום לשנות את האובייקט כדי להתאים אותו למסגרת, מפרידים בין שלושה דברים: מה המציאות דורשת, מה המערכת מסוגלת לבצע, ומה המבנה ההיסטורי גורם לנו להניח. לאחר ההפרדה ניתן לשמור רכיבים שעובדים ולשנות רק את היחסים שמונעים מהם לעבוד יחד.

כך מתקבל **Backward Reconstruction**: מתחילים מהתוצאה הנדרשת, חוזרים אל התנאים הדרושים לה, ורק אז בונים את הדרך אליה. השיטה מונעת מצב שבו פתרון נראה חדש אך למעשה משחזר את אותה מסגרת.

## אימות

כל שינוי צריך לחזור למציאות: תצפית, ראיה, שחזור, בדיקה והשוואה. WANGA מתאר את המחזור כ־**Observe → Represent → Reason → Act → Verify → Update Memory → Observe**. מערכת חיה חייבת להיות מסוגלת לשנות את הארכיטקטורה כאשר הדרישה או הראיות משתנות.

## סיכום

המשמעות של איך קופסה נוצרת היא שהפתרון אינו חייב להיות החלפה כוללת של המערכת. לעיתים השינוי החשוב ביותר הוא שינוי נקודת הייחוס והיחסים בין הרכיבים. כאשר הקופסה הופכת גלויה, אפשר להפסיק להילחם בתוך גבולותיה ולהרכיב את הפתרון לפי הדרישה.
