## 1. Executive summary

WANGA-LAB is being developed as an institutional AI architecture for coordinating heterogeneous AI models, Digital Model Agents, evidence, verification, formal reasoning and high-level cognitive escalation.

The architecture is not based on a single model. It is designed as a control and verification fabric around multiple model families.

The current long-term target is up to 5,000 model slots. A slot is an architectural identity, not a claim that a live model connection already exists.

## 3. Complete architecture

Operational plane:

WANGA OS → Global Work Manager → Model Fabric → Digital Model Agents → Providers / Runtimes

Epistemic and verification plane:

Evidence → Drift Forensics → Verification → Rational Logic

Cognitive plane:

Rational Logic ↔ Neural Thinking Machine

Memory plane:

Work Memory + Provenance + Bridge Events

Publication / integration plane:

Wix → public architecture and research surface

The Global Work Manager is the single global coordination layer. Local domain orchestration may exist, but no second independent global orchestrator is intended.

## 4. Rational Logic

Rational Logic is intended to formalize premises, rules, relations, constraints, contradictions, conclusions, missing premises and verification requirements.

It is deliberately separated from orchestration.

A model output is not treated as a proof merely because a model produced it.

The intended pipeline is:

INTAKE → NORMALIZE → EVIDENCE → RATIONAL REPRESENTATION → RULE / RELATION EVALUATION → MODEL / AGENT WORK → RATIONAL CHECK → VERIFICATION → NTM ESCALATION → WORK MEMORY

The next major development phase is to define the executable logical language, semantics, inference rules, contradiction handling, incomplete-premise behavior and machine-checkable tests.

## 5. Model Fabric and Digital Model Agents

The architecture allocates 5,000 model slots across capability families including reasoning, planning, language, coding, research, vision, audio, embeddings, reranking, mathematics, science, tool use, evaluation, drift, knowledge graphs, specialist models, local models, edge models and routing ensembles.

Each slot receives a Digital Model Agent identity.

A real model is enabled only after discovery, normalization, classification, role assignment, adapter resolution, capability probing, health checks, policy checks and verification.

No provider credential is intended to be stored in the model registry or cognitive envelope.

## 6. Perspective Layer

A future Perspective Layer is planned for up to approximately 1,000 defined perspective nodes.

A perspective can specify domain, question type, evidence requirements, reasoning rules, preferred model families, contradiction sensitivity, verification requirements and output schema.

The resulting conceptual matrix is:

MODEL × PERSPECTIVE × EVIDENCE × RATIONAL LOGIC

The 1,000 perspectives and 5,000 live connections are future scaling targets, not current deployment claims.

## 7. Evidence, Drift and Verification

The system separates observation from interpretation and verification.

The intended evidence chain is:

Document → Section → Claim ID → Evidence ID → Observation / Source → Run ID → Snapshot ID → Method Version

The architecture distinguishes observed facts, supported claims, hypotheses, refuted claims, derived metrics, inferences and verified results.

This is intended to make heterogeneous-model outputs auditable and reproducible.

## 17. Architecture discovery program — current build cycle

A dedicated three-track Architecture Discovery Program is now part of the Global Work Manager:

- **ARCH-01 Systems Architecture Scout** — orchestration, distributed control planes, workflow/state systems and model routing.
- **ARCH-02 Cognitive / Agent Architecture Scout** — agents, memory, planning, tool use, routing and evaluation.
- **ARCH-03 Verification / Infrastructure / IP Scout** — verification, provenance, observability, runtime, security and licensing.

The scouts are designed to examine relevant public GitHub repositories, extract architectural patterns, check license/provenance evidence, compare those patterns with WANGA interfaces, and produce bounded adaptation proposals.

This program is not an assertion of exhaustive GitHub coverage and does not copy proprietary code. External patterns remain proposals until they pass comparison, license review and verification. The program therefore increases the rate at which the existing architecture can learn from public engineering evidence without replacing WANGA's Global Work Manager or technical source of truth.

The repository contains the discovery program specification, schema, query plan and pattern matrix under docs/ARCHITECTURE_DISCOVERY_* and the execution entry point at scripts/architecture_discovery.py.

For financing discussions, this is a **current engineering capability being established**, not a claim that all external architectures have already been reviewed or integrated.
