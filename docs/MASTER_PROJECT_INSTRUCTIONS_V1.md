## 40 Principles
1. SYSTEM AS PRIMARY OBJECT — Treat the whole system as the primary work unit.
2. PRESERVE BEFORE REPLACE — READ → INSPECT → UNDERSTAND → COMPARE → PROPOSE → IMPLEMENT.
3. EVIDENCE BEFORE CLAIM — Distinguish OBSERVATION, RAW_EVIDENCE, NORMALIZED_DATA, DERIVED_METRIC, INFERENCE, HYPOTHESIS, PROPOSED_CHANGE, VERIFIED_RESULT, CONFLICT.
4. ONE GLOBAL WORK MANAGER — One global operational authority; bounded local orchestration only.
5. RATIONAL LOGIC CORE RESEARCH PRIORITY — Formal reasoning layer; not another orchestrator. Prioritize executable syntax, semantics, inference, contradiction handling, incomplete-premise handling, tests, counterexamples, and interfaces.
6. MODEL FABRIC — Up to 5,000 architectural model slots; slot != live model; activation requires discovery, normalization, classification, roles, adapter, capability, health, policy, registration, verification, enablement.
7. DIGITAL MODEL AGENTS — Each connected model gets a bounded DMA identity/control/interface layer with roles, capabilities, provenance, verification and NTM interface.
8. PERSPECTIVE LAYER — Up to ~1,000 Perspective Nodes defined by domain, question type, evidence requirements, reasoning rules, preferred model families, contradiction sensitivity, verification requirements, and output schema.
9. NTM — High-level cognitive synthesis, escalation, contradiction handling, routing and verification escalation; not an unrestricted executor.
10. VERIFICATION GATE — EXECUTE → COLLECT EVIDENCE → TEST → VERIFY → PROMOTE.
11. WORK MEMORY — Durable continuity layer recording observed state, decisions, constraints, changes, evidence, tests, verification, blocked/conflict state, and next action.
12. GITHUB AS TECHNICAL SOURCE OF TRUTH — READ → CLAIM → IMPLEMENT → TEST → VERIFY → COMMIT → PR → REVIEW; no direct main development.
13. HISTORY/BRANCH PRESERVATION — Do not delete, disable, rewrite, or erase preserved history.
14. AUTONOMOUS CONSTRUCTION — May observe, plan, modify isolated branches, test, verify, record; may not merge main, delete history, invent facts, bypass verification, or silently change invariants.
15. WIX/PUBLICATION — Wix is publication/external integration; GitHub is technical source of truth.
16. IP FIRST — Treat cumulative architecture, research, algorithms, formal logic, evidence, verification, agents, infrastructure and interfaces as IP assets; distinguish inventorship and ownership.
17. COMMERCIALIZATION — Develop technology and economic platform in parallel; never claim revenue without evidence.
18. INVESTOR/BANK ALIGNMENT — Financing materials must match actual technical status and distinguish BUILT, SPECIFIED, PROTOTYPED, TESTED, VERIFIED, PLANNED, HYPOTHETICAL.
19. VALUATION DISCIPLINE — Label ambitious positions as PROJECT VALUATION POSITION / SCENARIO, never as verified market valuation.
20. CAPITAL AND $1T SCENARIO — A $1T token issuance is a FUTURE FINANCING SCENARIO, not current cash, revenue, collateral, guaranteed funding, valuation, or return.
21. ECONOMIC VALUE CREATION LOOP — RESEARCH → IP → ENGINEERING → VERIFICATION → DEPLOYMENT → COMMERCIAL PILOT → REVENUE → LICENSING/ENTERPRISE SCALE → REINVESTMENT → NEW IP.
22. PRIORITY ENGINE — P0 integrity; P1 Rational Logic; P2 verification; P3 NTM+RL+Evidence; P4 Model Fabric; P5 Perspective scale; P6 commercialization; P7 presentation.
23. DEPENDENCY AWARENESS — Record dependencies before work and avoid building on unverified assumptions where verification is possible.
24. CONFLICT POLICY — Preserve both states, record evidence, block unsafe promotion, propose resolution, verify after resolution.
25. SECURITY — No credentials in registries, Work Memory, NTM envelopes, public docs, or evidence; least privilege and runtime secret resolution.
26. EXTERNAL PATTERNS — Learn lawful/open patterns at the pattern level; no third-party framework as global authority and no proprietary copying.

31. SYSTEM VALUE PERSPECTIVE — Consider IP accumulation, leverage, reuse, scalability, defensibility, licensing and integration value without inventing valuation.
