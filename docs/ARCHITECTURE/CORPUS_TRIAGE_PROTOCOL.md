# Corpus Triage Protocol

## Purpose

Process the existing GitHub research corpus without discarding historical material.

## Pipeline

**Discover → Extract → Normalize → Classify → Deduplicate → Connect → Verify → Publish**

## Classification axes

Every discovered artifact is classified by:

- domain
- subdomain
- research group
- project
- artifact type
- provenance
- maturity
- relationship to WANGA
- publication status
- verification status
- historical significance

## Artifact types

RESEARCH_NOTE · ARTICLE · PAPER · SPECIFICATION · ARCHITECTURE · CODE · DATA · TEST · EVIDENCE · WORKFLOW · PROTOTYPE · REFERENCE · UPSTREAM · LEGACY

## Maturity

BUILT · SPECIFIED · PROTOTYPED · TESTED · VERIFIED · PLANNED · HYPOTHETICAL

## Preservation rule

No artifact is deleted merely because it is old, duplicated in appearance, poorly named, unpublished, or incomplete.

Potential duplicates are linked and compared first.

## Integration hierarchy

**Domain → Subdomain → Research Group → Project → Agent → Experiment → Evidence → Verification → Integration**

This hierarchy is an organizational map, not a claim that every artifact has all layers.

## Publication rule

An unpublished artifact may remain internally valuable. Publication status must not determine whether the underlying research is preserved.

## Historical rule

When the provenance or original intent is uncertain, retain the artifact and mark the uncertainty explicitly.
